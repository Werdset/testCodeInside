# Детекция дорожных объектов

Небольшой воспроизводимый эксперимент на Ultralytics YOLO11n. Здесь важнее проверить данные и весь путь до TensorBoard, чем получить высокий mAP на сорока кадрах.

## Установка

Проверено с Python 3.12. Команды выполняются из корня проекта.

```bash
python -m venv .venv
```

Активация в PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

В Linux/macOS: `source .venv/bin/activate`.

```bash
python -m pip install -r requirements.txt
```

Для CUDA при необходимости установите соответствующие сборки torch/torchvision по инструкции PyTorch. Версии проекта — 2.5.1/0.20.1; CPU подходит для проверки. Интернет нужен для установки пакетов. Конфигурация использует архитектуру `yolo11n.yaml` со случайной инициализацией, поэтому веса скачивать не нужно.

## Подготовка выборки

```bash
python -m src.prepare_dataset --input test_data/traffic_v5_mini --output data/processed --seed 42
```

Исходные изображения и аннотации остаются в `test_data/traffic_v5_mini`. Результат записывается отдельно: YOLO-каталоги `images/{train,val,test}`, `labels/{train,val,test}`, `dataset.yaml`, `split.json`.

Проверяются декодирование изображений, соответствие аннотаций изображениям, число полей, конечность чисел, ID класса, положительные размеры и границы бокса. Отсутствующая аннотация считается ошибкой, а не отрицательным примером. Исправления десяти пропущенных аннотаций и остальных обнаруженных ошибок сохранены в `configs/annotation_fixes.json` с причинами. Проверка запускается повторно после применения исправлений.

Разбиение — 28/6/6 изображений. Близкие кадры одной сцены объединены в `configs/scene_groups.json`, чтобы не оказаться одновременно в train и val/test. Seed управляет разбиением групп; каждый класс во всех частях не гарантируется.

Результаты проверки:

- `reports/dataset_report.md` — статистика, решения и ограничения разметки;
- `reports/validation.json` — ошибки исходных файлов с номерами строк;
- `reports/samples/` — все 40 кадров с исправленными боксами;
- `reports/manifest.sha256` — хеши результата относительно `data/processed`.

Подготовка намеренно отказывается писать в непустой каталог. Для повторной проверки выберите другой `--output` и `--reports`; результат при том же seed будет побайтово одинаковым. Тест воспроизводимости также проверяет, что исходники не изменились. В репозитории достаточно мини-выборки, исправлений и manifest для восстановления обработанных данных.

`dataset.yaml` хранит пути относительно своего каталога. Запускайте обучение через модуль проекта: он разрешает их независимо от настроек datasets_dir Ultralytics. Временный YAML с разрешённым путём существует только во время запуска.

## Запуск эксперимента

Проверка окружения, датасета и записи событий, без обучения:

```bash
python -m src.run_experiment --config configs/yolo.yaml --data data/processed/dataset.yaml --dry-run
```

Короткое обучение на двух эпохах:

```bash
python -m src.run_experiment --config configs/yolo.yaml --data data/processed/dataset.yaml
```

Для доступной видеокарты: добавьте `--device 0`. Для изменения числа эпох: `--epochs 3`. Остальные параметры задаются в `configs/yolo.yaml`.

Каждый запуск создаёт уникальную папку `runs/<UTC-время>_<id>/`. Внутри:

- `metadata.json` — режим и статус, параметры, версии библиотек, Git commit и dirty-флаг, SHA-256 исходного кода и фактических файлов датасета;
- `config.yaml`, `dataset.yaml` — копии конфигураций;
- `tensorboard/events.out.tfevents.*` — события собственного `SummaryWriter`;
- `train/` — результаты обучения, CSV, графики и `weights/best.pt`, `weights/last.pt`;
- `test/` — отдельная оценка лучшего checkpoint на отложенной части, confusion matrix;
- `predictions/` — предсказания на всех test-кадрах;
- `test_metrics.json` — итоговые метрики test.

Dry-run сохраняет только конфигурацию, метаданные и проверку записи событий. В нём нет искусственных loss, mAP, checkpoint или предсказаний. При ошибке статус меняется на `failed`, сообщение сохраняется в метаданных, процесс завершается с ошибкой.

В конфигурации два прохода без предобучения: это проверка работоспособности, а не готовый детектор. Нулевые метрики и пустые предсказания на таком запуске возможны. Для осмысленного обучения замените `model` на `yolo11n.pt`, установите `pretrained: true` и увеличьте число эпох; первая загрузка весов требует сети.

## TensorBoard

```bash
tensorboard --logdir runs
```

Откройте адрес, который напечатает TensorBoard, обычно `http://localhost:6006`.

В Scalars записываются `train/box_loss`, `train/cls_loss`, `train/dfl_loss`, соответствующие `val/*`, `metrics/precision(B)`, `metrics/recall(B)`, `metrics/mAP50(B)`, `metrics/mAP50-95(B)` и learning rate. Значения поступают из callback `on_fit_epoch_end` после валидации. Повторный финальный callback не дублирует последнюю эпоху. Отдельные test-метрики имеют префикс `test/`.

Images содержит confusion matrix, графики и батчи Ultralytics, а также `predictions/*`. Text содержит параметры, версии и статус. `data/*_images` доступен и в dry-run. Встроенная интеграция TensorBoard отключена, чтобы не писать одни и те же события дважды.

## Проверки

```bash
python -m pytest -q
```

Тесты проверяют некорректную разметку, битые изображения, потерянные аннотации, воспроизводимость подготовки и отсутствие пересечения групп между частями. Порядок классов соответствует `classes.txt`, начиная с нуля.

Полные датасеты, веса, обработанные копии, логи и секреты исключены из Git. Исходная мини-выборка и визуализации входят в репозиторий; реальные локальные логи находятся в `runs/`.

Справка по использованному API: [callbacks Ultralytics](https://docs.ultralytics.com/usage/callbacks/) и [параметры обучения](https://docs.ultralytics.com/modes/train/).
